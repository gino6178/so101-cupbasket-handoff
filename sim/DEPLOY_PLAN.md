# 實機部署計劃（C920 + 兩支腕部相機，杯碗入籃）

寫於 2026-11-10。數字都是模擬結果：真實設定（`WX_REAL=1`）+ 物理 DR + 杯碗間距 3 cm。

## 一、現況審核

### 1. 目前沒有可以上實機的策略

| 系統 | 用到實機拿不到的資訊嗎 | 成功率 |
|---|---|---|
| 特權老師（BC-RNN + 殘差 cbdr3b） | 是（真值位姿、旗標、相對量） | 85.7% |
| 老師改吃相機定位，旗標與相對量仍用真值 | 是 | 68–77% |
| 學生 t0（腕部影像 + C920 定位） | 否 | 30–32% |
| 學生 t1（再加 C920 影像輸入） | 否 | 30–32% |
| 老師 + 手寫規則旗標 | 否 | 8–17% |
| 老師 + 學習式估計器 est1 | 否 | 2–6% |

### 2. 「估計器 → 老師」這條路應該放棄

est1 訓練到第 320 個 iteration，旗標準確率 98.4%、相對量誤差 1.25 cm，但成功率停在 6%。
把估計器的輸出逐項換回真值（各 256 回合）：

| 換回真值的項目 | 成功率 |
|---|---|
| 無（全部用估計） | 2.0% / 3.1% |
| 旗標 | 5.9% |
| 相對量全部 18 維 | 42.2% |
| 只有杯緣到夾爪 | 7.8% |
| 只有速度 | 3.5% |

- 沒有哪一項單獨修好就能解決；旗標和相對量要同時幾乎完美。
- 就算兩項都是真值，上限也只有 68–77%，低於 80% 的目標。
- 老師是在真值輸入上訓練的，對輸入誤差沒有容忍度。再加強估計器（包括讓它看影像）最多逼近 77%。

### 3. 所有結果都只在模擬裡驗證過

- 分割網路（`segnet_A2.pt`、`wsegnet1.pt`）只看過模擬渲染的影像，沒看過任何實機照片。
- 馬達動態沒有和實機比對過，模擬只是在 ±30% 範圍內隨機。
- 腕部相機的 100° 是對角還是水平視角、安裝位置，都還沒有用實物確認。

### 4. 實機程式只有舊任務的版本

`D:\NV_comp\real\sort_cell.py`（11/6）是舊的方塊分區任務。

可以沿用：
- lerobot Feetech 馬達驅動與關節對應（`JointMap`、`Arm`）
- 30 Hz 策略 / 120 Hz 下指令的控制迴圈
- 語音指令（faster-whisper）
- 安全流程（從 home 姿態開始、結束時鬆力矩、預設 dry run）

還沒有：
- C920 外參標定（現在只有四點單應，斜拍需要完整的內外參）
- 腕部相機擷取與鏡頭模型
- 分割網路推論、融合定位（`wx_top.py`、`wx_fuse.py` 目前依賴 Isaac Lab，不能直接在實機電腦上跑）
- 163 維觀測的組裝、LSTM 策略、杯碗與籃子的指令編碼

## 二、策略路線（模擬端）：重新設計（11/10）

原則：**策略從頭到尾只用實機拿得到的資訊訓練。** 不再先練一個吃真值的老師、再想辦法把真值補回來。

系統分成兩段，中間只傳「定位結果」：

1. **感知**：C920 + 兩支腕部相機 → 分割 → 融合定位，輸出每個杯碗和籃子的位置。這段已經有，誤差中位數 0.8 cm。
2. **控制**：有記憶的策略（LSTM），輸入只有定位結果、關節讀數、自己上一步的動作。不用進度旗標、真值相對量、物體速度。

保留：模擬環境與幾何、兩個分割網路、融合定位、特權老師（只用來暖身和當評論家）、實機馬達驅動程式。

丟掉：估計器 est1、手寫規則旗標、「老師吃相機定位」、C920 影像直接進學生的 A/B、dt1。

步驟：

| 步驟 | 內容 | 過關條件 |
|---|---|---|
| 1. 定位誤差模型 | 把融合定位量到的誤差（中位數、p90、遮擋時凍結、腕部 16% 離群值、延遲）做成不用渲染的噪聲模型，訓練才跑得快 | 同一個策略在「噪聲模型」和「真的渲染 + 分割」下成功率差 < 5 個百分點 |
| 2. 暖身 | 用特權老師當標籤，DAgger 練出只吃定位結果的 LSTM 基底 | ≥ 50% |
| 3. 強化學習 | 在基底上做殘差 PPO：演員吃定位結果，評論家吃真值；遮夾爪通道、稀疏獎勵、gamma 0.998 | 噪聲模型下 ≥ 85% |
| 4. 驗收 | 用真的渲染 + 分割 + 融合定位評估，512 回合 × 2 seed，並看放大的影片確認沒有取巧 | ≥ 80% |

風險：
- 步驟 1 的噪聲模型如果和真實管線差太多，步驟 3 練出來的策略到步驟 4 會掉分。所以步驟 1 要先單獨驗證。
- 夾杯緣需要毫米級對準，只靠 0.8 cm 的定位可能不夠。如果步驟 3 卡在夾取，再把腕部影像加進策略輸入。
- 沒有保證能到 80%。步驟 3 跑 150 個 iteration 還不到 60% 就要降低任務難度（見第五節）。

## 三、實機端（不需要等策略，可以現在開始）

### 階段 1：硬體與標定

| 項目 | 做法 | 驗收標準 |
|---|---|---|
| 場景佈置 | 照 `SCENE_SETUP.md` | 位置誤差 ±3 cm 內 |
| 手臂標定 | lerobot 標定；確認關節零點、方向、極限與模擬一致 | 夾爪碰桌面 4 個已知點，誤差 < 5 mm |
| C920 設定 | 鎖定對焦、曝光、白平衡；1280×720 MJPEG | 連續 5 分鐘畫面亮度不漂 |
| C920 標定 | 棋盤格求內參；桌面 4 個以上 AprilTag 求外參 | 重投影 < 1 px；已知位置的杯子定位 < 1 cm |
| 腕部相機 | 確認 320×240、視角定義；棋盤格求內參與畸變；量安裝位置 | 安裝誤差 ±4 mm、±4° 內；視角與 `WX_WRIST_DFOV` 相符 |
| 延遲 | 對著閃燈或計時器量三支相機的延遲 | C920 ≤ 133 ms；腕部 ≤ 100 ms |

### 階段 2：收集實機影像

- C920：300 張以上，杯碗和籃子位置各不相同，包含手臂伸進畫面、杯碗疊放、不同光線。
- 腕部：每支 300 張以上，包含接近杯緣、夾住、搬運、放進籃子。
- 其中 20 個擺放要用尺量出杯碗和籃子的真實位置，用來驗證定位。

### 階段 3：感知驗證

1. 把兩個分割網路直接跑在實機影像上，看分類結果。
2. 用量過位置的 20 個擺放算定位誤差。
3. 不達標就標註 50–100 張實機影像做微調，並把實機的顏色、光線加進模擬的隨機範圍。

驗收標準（對齊模擬中的誤差）：
- 無遮擋的杯碗：p90 ≤ 2 cm
- 籃子中心：≤ 1.5 cm；yaw ≤ 4°

### 階段 4：動態比對

1. 把模擬裡一段成功回合的關節指令原樣在實機上播放（空桌、不放物件）。
2. 比較實機與模擬的關節軌跡：追蹤誤差、延遲、過衝。
3. 量夾爪開合的角度與所需時間。
4. 結果用來設定模擬 PD 增益的中心值；偏差超過 ±30% 就要改模擬並重新訓練。

驗收標準：指令到動作的延遲 ≤ 2 個控制步（67 ms）；軌跡終點誤差 < 1 cm。

## 四、實機執行程式（`real/cup_cell.py`）

要寫的模組：

1. **擷取**：三支相機各一個執行緒，帶時間戳。
2. **感知**：分割推論 + 融合定位。先把幾何常數從 `cup_basket_env_cfg.py` 抽成不依賴 Isaac Lab 的模組。
3. **觀測組裝**：和 `ProprioReal` 輸出完全相同的 163 維排列。
4. **策略**：LSTM 學生 + 殘差。
5. **指令**：語音 → 杯碗與籃子的 one-hot。
6. **動作**：關節目標 = 量測值 + 0.033 × 動作；夾爪看符號開合。
7. **安全**：關節極限、單步速度上限、工作區邊界、鍵盤急停、預設 dry run。

兩個必做的檢查：
- **一致性測試**：把這套實機程式接回模擬跑一次，成功率要和模擬中的評估相同（差距 < 3 個百分點）。這能在上實機前抓出觀測排列、單位、延遲的錯誤。
- **速度測試**：在實機電腦上量整個迴圈，要穩定維持 30 Hz（感知 10 Hz）。

## 五、分段實測與退路

每一段做 20 次，記錄夾取 / 抬起 / 到籃上 / 放下 / 鬆開各步驟的成功率，和模擬的同一張表比較。

1. Dry run：不出力，只看觀測數值和預測動作是否合理。
2. 單臂、單個杯子、指定籃子。
3. 單臂、碗。
4. 雙臂同時、各一個容器。
5. 疊放（杯疊杯、碗疊碗）。
6. 完整任務 50 次，位置、籃子角度、光線都變化。

失敗分類後的處理：
- 定位偏差 → 加實機影像微調分割網路。
- 動作跟不上或過衝 → 調整模擬增益中心後微調策略。
- 夾取位置對但夾不起來 → 檢查夾爪摩擦、杯壁厚度與模擬是否一致。

如果模擬端到不了 80%，可以考慮的降難度選項（都需要你決定）：
- 杯碗間距從 3 cm 放寬到 5 cm。
- 兩臂輪流動作，不同時。
- 先不做疊放。

- 腕部相機的規格書（確認 100° 是對角還是水平）。
